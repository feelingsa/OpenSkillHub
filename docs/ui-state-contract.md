# 补充 UI 状态合同

以下状态不在当前 SVG 设计导出中明确呈现，因此属于产品补充实现。它们必须使用共享设计令牌，并通过功能测试和可访问性语义验收，而不是宣称与 SVG 像素一致。

## 用户端

| 状态 | 触发条件 | 用户可见内容 | 允许操作 |
| --- | --- | --- | --- |
| 登录提交中 | 登录请求未结束 | 禁用提交按钮、加载文本和 `aria-busy` | 取消或等待 |
| 登录失败 | 凭据无效、会话过期或服务拒绝 | 不泄漏具体账户信息的错误提示 | 修改输入后重试 |
| 目录扫描中 | 首次或手动同步尚未完成 | 保留公共壳层和骨架卡片 | 刷新状态 |
| 空目录 | 扫描成功但没有启用 Skill | 空状态和管理员联系说明 | 返回或刷新 |
| OpenCode 离线 | 服务健康检查失败 | 目录仍可浏览，运行入口禁用且说明原因 | 重试检查 |
| 页面生成中 | `pageStatus` 为 `queued`/`generating` | 进度、最后状态和通用操作页入口 | 使用通用页或稍后刷新 |
| 无权访问 | 用户不拥有 Skill、运行或产物权限 | 403 状态页，不显示资源元数据 | 返回目录 |
| 运行中 | `RunState` 未终止 | 队列、事件、日志、问题、权限和产物流 | 回答、低风险一次授权、终止 |
| 运行失败 | `run.failed` | 脱敏错误摘要、已产物和重新运行入口 | 重新运行或返回 |

## 管理端

| 状态 | 触发条件 | 用户可见内容 | 允许操作 |
| --- | --- | --- | --- |
| 无管理员权限 | 非管理员访问 `/admin/*` | 通用 403 页面 | 返回用户端 |
| 服务部分不可用 | Node、OpenCode、数据库、扫描/生成/运行队列任一异常 | 明确区分健康和异常组件，不暴露路径或凭据 | 查看脱敏诊断、重试允许操作 |
| 表格加载/空/错误 | 管理列表请求进行、为空或失败 | 骨架/空状态/可重试错误 | 刷新、修改筛选 |
| 扫描或生成中 | 后台任务执行 | 当前阶段、开始时间、任务归属和取消/重试状态 | 仅管理员可控制任务 |
| 高风险权限请求 | Skill 请求超出低风险一次授权范围 | 风险摘要和最小权限范围 | 允许一次、持久允许或拒绝；持久允许仅管理员 |

## 桌面端与可访问性

- 项目仅支持桌面端，基准视口为 `1440 x 900`。移动端布局、触摸交互和响应式断点不属于实现或验收范围，桌面端页面不得因迁就移动端而改变设计还原结果。
- 所有异步状态使用可见文本和合适的 `aria-live`/`aria-busy`，不能只用颜色、动效或图标表达。
- 键盘可到达卡片、搜索/筛选、弹窗、表单、权限按钮和产物操作；弹窗开启后焦点进入弹窗，关闭后回到触发元素。
- `prefers-reduced-motion: reduce` 下，卡片、弹窗、路由和状态动效直接到达最终状态，但不改变焦点、可见性或业务结果。

## 基础验收命令

M1 建立项目脚本后，所有提交至少执行下列命令；命令在实现前不视为已通过：

```text
npm.cmd run typecheck
npm.cmd test
npm.cmd run test:api
npm.cmd run test:browser
npm.cmd run audit:design
```

每个新增页面还要在其映射的桌面端视口检查上述状态合同。视觉差异仅应用于 `design-sources.md` 定义的 1:1 壳层区域。
